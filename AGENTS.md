# Project instructions

- This is the multilingual (Russian, English, French) Forbidden Stars card and FAQ site. Russian (`page/locales/ru/`) is the complete base; `en/` and `fr/` are layered on top and fall back to it. Preserve Russian terminology and source links.
- Localization infrastructure (`page/script/i18n.js`, `FSI18n`): `ru` is the complete base locale; `en` and `fr` are partial overlays under `page/locales/<lang>/`, merged over the Russian files (objects by key, arrays of objects by index, anything else replaced). Whatever an overlay lacks, or fails to load, falls back to Russian. Language comes from `?lang=`, then `localStorage` (`fs-lang`), then the browser language, then `ru`; the selector lives in the header. Each locale holds `ui.json` (interface strings, `t('key')`, `{name}` placeholders and plural forms), `data/FAQ.json` (loaded with `replace`: an overlay FAQ replaces the Russian one as a whole), `data/cardnames.json`, `factions/general.json`, and per faction `faction.json` and `text.json`. Card images in `page/factions/` are shared by all languages and are never localized; the only images under `locales/en/` are the English `faction_card/card.jpg` files. Add a language by registering it in `languages` in `i18n.js` and adding its `locales/<lang>/` overlay; never copy Russian text into an overlay just to fill gaps.
- Print: `catalog.js` addresses localized data by logical path (`localePath`). Russian print sets fingerprint only the Russian files; other languages also fingerprint their overlay files. Printing is Russian-only for now, so do not enable it for another language without covering its overlay in the source fingerprints.
- Deployment: `.github/workflows/` publishes the `page/` directory to GitHub Pages on pushes to `main` and `locales-en-import` (and manually). `page/` is the site root, so nothing outside it is served; `_config.yml` is not used by that workflow.
- Keep the three READMEs in sync: `README.md` (English, default), `README.fr.md` and `README.ru.md`, each with the language switcher line under the title.
- Darkest Dawn (`dd`) is permanently excluded by the project owner. Do not add, translate, synchronize, or recommend it. Its absence is intentional and must not be reported as a content gap.
- Keep this repository limited to the website in `page/`, its assets, READMEs, licence, site configuration and project instructions. Keep development tooling, tests, generated previews, exports and review reports outside the repository unless explicitly requested.
- Supported expansion folders are `base`, `gif`, `sow` and `dl` (The Dying Light). The last reviewed English upstream is `Frytkownica/Forbidden_Star` at `a31d0e9dd83d82691389341c7f412d9ff787fdc2`. Keep legacy `tdl` card routes working through `navigation.js`; new paths and links use `dl`, matching upstream. SoW folders `adepta_sororitas`, `adeptus_mechanicus` and `dark_eldar` map to `adeptasororitas`, `adeptusmechanicus` and `darkeldar`.
- Prepare review evidence outside the repository before applying rule changes. Do not automatically overwrite Russian text or advance the reviewed upstream commit. Preserve source citations and stable card/FAQ identifiers.
- Preserve explicit token wording in source JSON. Token icons are a presentation preference, not a replacement for canonical rules text.
- TDL terminology uses «Тысяча Сынов», «Тзаангор», «Солнечный Дозор» and «Гиканаты». Keep card-name lookups synchronized with rendered titles. Fan-created ship names retain their source-specific wording; do not present uncertain community translations as official GW terminology.
- Order types are «Планирование» (Strategize), «Развёртывание» (Deploy), «Доминирование» (Dominate) and «Продвижение» (Advance). Capitalize «Приказ» and «Фаза», including inflected forms, when paired with a named order or phase (for example, «Приказа Доминирования», «Фазу Действий»). Do not substitute «Стратегия», «Перемещение» or «Наступление» for these types; preserve ordinary movement wording and source-specific card titles.
- When migrating existing Russian raster cards to text templates, use the current Russian images and preserve approved samples. Do not use FS League/Notion wording variants or silently correct rules during this visual migration.
- Validate JSON data and JavaScript syntax; check the site in a browser when changing navigation, accessibility, rendering or font glyphs. Keep temporary verification scripts and output outside the repository.
- Grid, search and printing share `page/script/catalog.js`, built from the existing faction manifests and text. `page/data/print-catalog.json` contains print settings, eligible expansions and control IDs only; do not add a second card/faction list or stored array indices.
- Use `FSCache.json` for shared session data; failed requests must remain retryable. Print source fingerprints must match the local generator's current source files.
- The reusable release checks and visual references live in the sibling `Forbidden_Star-QA` directory. Follow its README; do not automatically replace visual baselines after a failing comparison.
